1Qué vamos a armar

El collar AgroNeck manda su posición y temperatura por radio LoRa. La Raspberry Pi la recibe con la placa SX1278, la convierte a JSON y la reenvía por la red a MooPing, que corre en tu PC dentro de Docker. MooPing la guarda, calcula alertas y la muestra en la web.

Qué necesitás

QuéDetalle
Una PCWindows 10/11 o macOS, con 8 GB de RAM o más y unos 10 GB libres. Ahí corre MooPing.
Raspberry PiPi Zero 2 W con la placa AgroBot (radio SX1278), tarjeta microSD de 16 GB o más y su fuente.
Collar AgroNeckYa flasheado (si no, ver firmware/AgroBot/Setup.md, paso 6). Para la primera prueba no hace falta: la sección 7 simula una lectura.
Una red WiFiLa PC y la Pi tienen que estar en la misma red. La Pi Zero 2 W solo usa WiFi de 2,4 GHz.
Antes de empezar

Esta guía describe el código que está en la rama main del repositorio. Si ya tenías el proyecto clonado, hacé git pull antes de seguir (en la PC y en la Pi).

Checklist

  • Docker Desktop instalado y abierto, con "Engine running" (sección 2).
  • MooPing andando en http://localhost:5173 con la demo cargada (sección 3).
  • IP de la PC anotada y puerto 4001 permitido en el firewall (sección 4).
  • Pi con SPI habilitado y el receptor compilado (secciones 5 y 6).
  • Lectura simulada visible en MooPing (sección 7).
  • Collar real visible en el mapa (sección 8).

2PC: instalar Docker, Git y Python

MooPing corre en 4 contenedores de Docker. start.py es un script de Python que los levanta, y Git sirve para bajar el código. Instalá las tres cosas según tu sistema.

Windows 10 / 11

  1. WSL2 (Docker lo necesita). Abrí PowerShell como administrador (clic derecho → "Ejecutar como administrador") y corré: 
    wsl --install
    Reiniciá la PC cuando termine.
  2. Docker Desktop: bajalo de docker.com/products/docker-desktop e instalalo con la opción "Use WSL 2 instead of Hyper-V" tildada. Reiniciá si te lo pide.
  3. Git: git-scm.com/download/win, con las opciones por defecto.
  4. Python 3.12 o más: python.org/downloads. En la primera pantalla del instalador tildá "Add python.exe to PATH".

macOS 13 o más

  1. Docker Desktop: docker.com/products/docker-desktop. Elegí la versión de tu chip: Apple Silicon (M1/M2/M3/M4) o Intel (lo ves en → Acerca de esta Mac). Arrastralo a Aplicaciones y abrilo.
  2. Git: en la Terminal corré 
    xcode-select --install
    y aceptá la instalación.
  3. Python 3: python.org/downloads (instalador .pkg) o, si usás Homebrew, brew install python.

Abrir Docker y verificar

Abrí Docker Desktop y esperá a que abajo a la izquierda diga "Engine running" (la primera vez tarda un poco y puede pedirte aceptar los términos). Docker tiene que estar abierto cada vez que uses MooPing.

Después abrí una terminal (PowerShell en Windows, Terminal en macOS) y verificá:

docker --version
docker compose version
git --version
python --version      # en macOS: python3 --version

Los cuatro tienen que responder con un número de versión. Si alguno dice "no se reconoce" o "command not found", cerrá y volvé a abrir la terminal; si sigue igual, reinstalalo (en Windows, revisá que Python tenga tildado "Add to PATH").

3PC: bajar MooPing y correr start.py

Clonar el repositorio

En la terminal, andá a la carpeta donde quieras guardar el proyecto (por ejemplo Documentos) y corré:

git clone https://github.com/Nossva/MooPing.git
cd MooPing/mooping       # en Windows también funciona: cd MooPing\mooping

Levantar todo

python start.py          # en macOS: python3 start.py

start.py hace, en orden:

  1. Revisa que Docker esté instalado y corriendo.
  2. Corre docker compose up -d --build: construye y levanta los 4 contenedores.
  3. Aplica a la base los scripts db/upgrade-*.sql (actualizaciones del esquema).
  4. Espera a que respondan la API (/api/health/) y la web.
  5. Abre http://localhost:5173 en el navegador.
La primera vez tarda

Entre 3 y 10 minutos: Docker baja las imágenes e instala las dependencias. Las siguientes veces arranca en segundos. Mientras tanto vas a ver mensajes como "Esperando a que responda…". Es normal.

Cuando termina, muestra:

MooPing está andando: http://localhost:5173/  (API: http://localhost:8000/api/health/)

Cargar los datos de demostración

La base arranca vacía. Cargá el establecimiento de demo "El Ombú" (12 animales, collares, gateways y alertas):

docker compose exec backend python manage.py seed_demo
Demo lista: 12 animales, 14 collares, 1072 lecturas, 4 alertas abiertas.
Login: demo@mooping.app / mooping123

Si dice Ya existe "El Ombú", la demo ya estaba cargada: no hace falta hacer nada. Para dejarla como nueva: docker compose exec backend python manage.py seed_demo --reset.

Entrar

En http://localhost:5173 tocá "Probar con Establecimiento Demo", o entrá con demo@mooping.app / mooping123 (usuario Dueño, puede editar todo).

Los 4 contenedores

Para ver que estén corriendo: docker compose ps (desde la carpeta mooping).

ContenedorPuertoQué hace
mooping-db5432 (solo esta PC)Base de datos PostgreSQL + PostGIS.
mooping-backend8000La API que usa la web.
mooping-telemetry4001Recibe las lecturas de la Raspberry Pi por TCP y genera alertas.
mooping-frontend5173La página web (React).

4PC: dejar que la Raspberry llegue

La Pi le va a mandar los datos a tu PC al puerto 4001. Para eso necesitás la IP de la PC en la red WiFi y que el firewall deje pasar ese puerto.

La IP de tu PC

Windows

ipconfig

Buscá el bloque "Adaptador de LAN inalámbrica Wi-Fi" y anotá la Dirección IPv4 (por ejemplo 192.168.1.50).

macOS

ipconfig getifaddr en0

Devuelve la IP directamente. Si no muestra nada, probá con en1, o mirala en Configuración → Wi-Fi → Detalles.

En esta guía usamos 192.168.1.50 como ejemplo

Reemplazala siempre por la IP real de tu PC. Si la PC cambia de red, la IP cambia.

Firewall

Windows

En PowerShell como administrador:

New-NetFirewallRule `
  -DisplayName "MooPing telemetria" `
  -Direction Inbound -Protocol TCP `
  -LocalPort 4001 -Action Allow `
  -Profile Private

La regla vale para redes privadas: en Configuración → Red e Internet → Wi-Fi → (tu red), marcala como "Red privada". Si Windows muestra un aviso del firewall para Docker, tocá Permitir.

macOS

Configuración del Sistema → Red → Firewall. Si está desactivado, no hay que hacer nada. Si está activado: Opciones… → agregá Docker y elegí "Permitir conexiones entrantes". También podés tocar Permitir cuando macOS lo pregunte.

Opcional (recomendado): clave de telemetría

Sin clave, MooPing acepta lecturas de cualquiera en la red. Con una clave, solo de la Pi que la conoce. Generá una:

python -c "import secrets; print(secrets.token_urlsafe(24))"   # macOS: python3

Abrí mooping/backend/.env con un editor de texto (lo crea MooPing la primera vez), agregá al final la línea con tu clave y reiniciá la telemetría:

TELEMETRY_API_KEY=<la-clave-que-generaste>
docker compose restart telemetry

Anotá la clave: la vas a pasar a la Pi como TELEMETRY_KEY. No la subas a git ni la pegues en grupos (.env ya está en .gitignore).

5Raspberry Pi: sistema, SPI y conexión de la placa

Instalar Raspberry Pi OS

  1. En la PC instalá Raspberry Pi Imager (raspberrypi.com/software) y poné la microSD.
  2. Elegí: dispositivo Raspberry Pi Zero 2 W, sistema Raspberry Pi OS Lite (64-bit), y tu tarjeta.
  3. Cuando pregunte por la personalización, tocá "Editar ajustes" y completá:
    • Nombre de host: agrobot
    • Usuario y contraseña (anotalos).
    • WiFi: la misma red que la PC (2,4 GHz) y el país AR.
    • Pestaña Servicios: Habilitar SSH con contraseña.
  4. Grabá la tarjeta, ponela en la Pi y enchufala. Esperá 2 o 3 minutos a que arranque.

Entrar a la Pi desde la PC

ssh <tu-usuario>@agrobot.local

La primera vez pregunta si confiás en el equipo: escribí yes. Si agrobot.local no funciona (pasa en algunas redes), buscá la IP de la Pi en la página del router y usá ssh <tu-usuario>@<ip-de-la-pi>.

Pi Desde acá, todos los comandos de las secciones 5 a 8 que digan "Pi" se corren dentro de esta sesión SSH.

Instalar herramientas

sudo apt update
sudo apt install -y git cmake build-essential netcat-openbsd

Habilitar SPI (la radio se comunica por SPI)

sudo raspi-config

Andá a Interface Options → SPI → Yes, salí con Finish y reiniciá:

sudo reboot

Volvé a entrar por SSH y verificá que existan los dos dispositivos:

ls -l /dev/spidev0.0 /dev/gpiochip0

Si dice No such file or directory para spidev0.0, SPI no quedó habilitado: repetí el paso.

Conexión de la placa SX1278

Si usás la placa AgroBot ya armada, viene conectada así. Si cableás a mano, seguí esta tabla (numeración BCM y pin físico del header de 40 pines):

Señal SX1278GPIO (BCM)Pin físico
MOSI1019
MISO921
SCLK1123
CS824
RESET2522
DIO02418
Conectá la antena antes de encender

Usar la radio sin antena puede dañar el módulo. El receptor y el collar trabajan en 433 MHz: la antena tiene que ser para esa frecuencia.

6Raspberry Pi: compilar el receptor

Pi

git clone https://github.com/Nossva/MooPing.git
cd MooPing/firmware/AgroBot/firmware
cmake -S . -B build
cmake --build build -j2

En la Pi Zero tarda uno o dos minutos. Al final tienen que existir dos programas:

ls build/agrobot-lora-receiver build/agro-neck-client

agrobot-lora-receiver es el que usamos: escucha la radio y reenvía cada lectura. (agro-neck-client es un simulador del sistema AgroBot, no lo necesitamos para MooPing.)

Cómo se configura el receptor

No hay que tocar el código: todo se pasa con variables al arrancarlo.

VariablePara quéEjemplo
TELEMETRY_TARGETSA quién le manda cada lectura: ip:puerto, hasta 4 separados por coma. Sin la variable usa 127.0.0.1:4001.192.168.1.50:4001
GATEWAY_IDQué gateway recibió el paquete. Tiene que existir en MooPing: la demo trae AGROBOT-01 ("Molino Sur") y AGROBOT-02 ("Casco").AGROBOT-01
TELEMETRY_KEYLa clave de la sección 4, si la configuraste. Si no, no la pongas.<tu-clave>
Las variables van después de sudo

sudo borra las variables de entorno. Por eso se escribe sudo TELEMETRY_TARGETS=… ./build/agrobot-lora-receiver y no al revés.

7Prueba sin radio: ¿llega la red?

Antes de sumar la radio y el collar, comprobamos que la Pi llegue a MooPing mandando una lectura inventada a mano. Si esto funciona, cualquier problema posterior es de la radio, no de la red.

PC Dejá mirando el log de la telemetría

docker compose logs -f telemetry

(Desde la carpeta mooping. Para salir: Ctrl+C.)

Pi Mandá una lectura de prueba

Reemplazá la IP por la de tu PC:

printf '%s\n' '{"ID":"COLLAR-999", "LAT":-34.70, "LONG":-58.24,
  "TEMP":"38.5", "GW":"AGROBOT-01"}' | nc -N -w 3 192.168.1.50 4001

Es un solo comando de dos líneas: copialo entero. Si configuraste clave, agregá , "KEY":"<tu-clave>" antes de la última llave:

printf '%s\n' '{"ID":"COLLAR-999", "LAT":-34.70, "LONG":-58.24,
  "TEMP":"38.5", "GW":"AGROBOT-01", "KEY":"<tu-clave>"}' | nc -N -w 3 192.168.1.50 4001

PC Qué tenés que ver

En el log de la telemetría aparece una línea así (la IP entre corchetes y los números cambian):

mooping-telemetry  | [192.168.65.1] lectura 1090 collar 33

Y en la web, en Equipos, aparece la tarjeta "Detectados sin vincular" con el collar de prueba recibido por "Molino Sur":

Si no aparece nada en el log, la lectura no llegó: mirá la sección 9 (IP, firewall, misma red). Si aparece descartada: falta KEY…, la clave no coincide.

Limpiar la prueba

COLLAR-999 no existe en la realidad. No lo vincules; desaparece solo de la lista a los 7 días. Para borrarlo ya: docker compose exec db psql -U mooping -d mooping -c "DELETE FROM devices WHERE device_uid='COLLAR-999'"

8Prueba real: receptor y collar

Pi Arrancar el receptor

cd ~/MooPing/firmware/AgroBot/firmware
sudo TELEMETRY_TARGETS=192.168.1.50:4001 \
     GATEWAY_ID=AGROBOT-01 \
     ./build/agrobot-lora-receiver

Con clave:

sudo TELEMETRY_TARGETS=192.168.1.50:4001 \
     GATEWAY_ID=AGROBOT-01 \
     TELEMETRY_KEY=<tu-clave> \
     ./build/agrobot-lora-receiver
Forwarding telemetry to 192.168.1.50:4001
Gateway ID: AGROBOT-01
Telemetry key: not set (backends must accept any sender)
SX1278 version: 0x12
Listening for AgroNeck LoRa packets at 433 MHz
  • Telemetry key: set si pasaste la clave.
  • SX1278 version tiene que ser 0x12. Si da 0x00 o 0xFF, la Pi no está hablando con la radio: revisá el cableado y que SPI esté habilitado.
  • El receptor queda escuchando. No cierres esta terminal; para pararlo, Ctrl+C.

Despertar el collar

El AgroNeck duerme hasta que detecta movimiento: movelo. Con cada transmisión la Pi muestra (los valores cambian):

Raw LoRa packet (14 bytes): 7A 00 9A 99 19 42 ...
Received collar=122 temperature=38.40 C latitude=-34.707652 longitude=-58.242300
Signal RSSI=-88 dBm SNR=7.25 dB

Si aparece connect to telemetry backend … después de cada paquete, la lectura no le está llegando a MooPing: volvé a la sección 7. El GPS puede tardar varios minutos en conseguir señal al aire libre; mientras tanto el collar manda latitud y longitud en 0 y MooPing guarda la lectura sin posición.

PC Vincular el collar en MooPing

  1. En Equipos, el collar aparece en "Detectados sin vincular" como COLLAR-122. Tocá Vincular: el número y la etiqueta (C-122) ya vienen cargados. Confirmá con Vincular.
  2. Para verlo en el mapa tiene que estar en un animal. En la demo todos los animales ya tienen collar, así que liberamos uno: en Collares en campo buscá C-305, tocá Configurar y después "Desvincular de Novillo #305" (pide confirmación).
  3. Buscá C-122 (o usá el filtro Sin asignar), tocá "Vincular a un animal", elegí Novillo #305 y confirmá.
  4. Volvé a mover el collar para que mande otra lectura. En Monitoreo, el Novillo #305 muestra Collar #C-122, la señal y su posición en el mapa.
¿Por qué hay que esperar otra lectura?

Las lecturas que llegaron antes de asignar el collar no tenían animal. La posición del animal se actualiza con la primera lectura que llega después de asignarlo.

Además, en Equipos y en Soporte el gateway Molino Sur pasa a figurar conectado mientras lleguen lecturas.

Al terminar, para dejar la demo como estaba: docker compose exec backend python manage.py seed_demo --reset.

Opcional: mandar también a AgroBot

Si en la Pi corre el servidor AgroBot (ver firmware/AgroBot/Setup.md), el receptor puede mandar cada lectura a los dos sistemas a la vez:

sudo TELEMETRY_TARGETS=127.0.0.1:4001,192.168.1.50:4001 \
     GATEWAY_ID=AGROBOT-01 \
     ./build/agrobot-lora-receiver

Si uno de los dos está apagado, el otro sigue recibiendo: cada envío corta a los 2 segundos.

9Problemas frecuentes

En la PC

SíntomaQué hacer
start.py: "No encontré Docker"Docker Desktop no está instalado, o la terminal se abrió antes de instalarlo: cerrala y abrí una nueva.
start.py: "Docker no está corriendo"Abrí Docker Desktop y esperá "Engine running".
"python" no se reconoce (Windows)Reinstalá Python tildando "Add python.exe to PATH", o usá py start.py.
port is already allocated / puerto ocupadoOtro programa usa 5432, 8000, 4001 o 5173. Creá mooping/.env con, por ejemplo, DB_PORT=5433, BACKEND_PORT=8001, TELEMETRY_PORT=4002 y volvé a correr start.py. Si cambiás TELEMETRY_PORT, usá ese puerto en la Pi.
La web dice "No se pudo cargar"El backend se está reiniciando: esperá unos segundos. Si sigue: docker compose logs --tail 40 backend.
Login: "Email o contraseña incorrectos" con la demoFalta cargar la demo: docker compose exec backend python manage.py seed_demo.
"Demasiados intentos"Hay un límite de intentos de login: esperá un minuto.
Después de actualizar, la web pide entrar de nuevoNormal: la sesión ahora usa una cookie segura. Volvé a entrar.

En la Raspberry Pi

SíntomaQué hacer
open SPI device: No such file or directorySPI no está habilitado: sudo raspi-config → Interface Options → SPI → Yes, y reiniciá.
open SPI device: Permission deniedFalta sudo adelante del comando.
SX1278 version: 0x00 o 0xFFLa Pi no ve la radio: cableado, placa mal asentada o SPI apagado.
connect to telemetry backend 192.168.1.50:4001: Connection refusedLa IP es de la PC pero MooPing no escucha: ¿está corriendo? (docker compose ps) ¿Cambiaste TELEMETRY_PORT?
… Connection timed out o No route to hostLa Pi no llega a la PC: IP equivocada, firewall (sección 4), o la PC y la Pi en redes distintas (ojo con redes de "invitados", que aíslan los equipos).
Discarded LoRa packet with CRC errorEl paquete llegó dañado: acercá el collar, revisá las antenas.
No aparece nada al mover el collarCollar sin batería o dormido; las dos radios tienen que estar en 433 MHz.
Invalid telemetry target '…' (expected host:port)Falta el puerto: 192.168.1.50:4001, no 192.168.1.50.
Ignoring GATEWAY_ID / TELEMETRY_KEY: use up to …Usá solo letras, números, -, _ y ., sin espacios ni comillas.

En MooPing (log de telemetry)

SíntomaQué hacer
descartada: falta KEY o no coincide con TELEMETRY_API_KEYLa clave de la Pi (TELEMETRY_KEY) no es igual a la de backend/.env, o se cambió .env y falta docker compose restart telemetry.
Llega la lectura pero no aparece en "Detectados"Falta GATEWAY_ID, o el gateway no existe en MooPing (con la demo: AGROBOT-01 o AGROBOT-02). Si el collar ya estaba vinculado, no aparece ahí: buscalo en Collares en campo.
El collar figura "Sin señal"No llegan lecturas hace más de 30 minutos. Revisá que el receptor siga corriendo.
